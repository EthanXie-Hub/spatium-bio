# Contributing

This is a solo, in-public learning project. Contributions are welcome
in any of these forms:

- **Issues** — point out something that's wrong (especially the
  science), suggest a paper I should read, or flag a claim that
  doesn't match the evidence in the repo.
- **Pull requests** — small, focused changes are easier to review.
  For anything larger than a typo, please open an issue first so we
  can agree on direction.
- **Email** — `nyssa520ethan@gmail.com` for anything that doesn't fit
  GitHub.

## What I care about

- Honesty over impressiveness. If a change overstates what the repo
  can do, I will push back.
- Reproducibility. New scripts should be runnable end-to-end on a
  fresh clone with the documented setup.
- Plain language in docs. No paper-review voice.

## What I don't care about (yet)

- Formal coding conventions beyond what `ruff` enforces on Python and
  `eslint` on TypeScript.
- Test coverage targets. New code should have at least one test;
  the rest is taste.

## Code of conduct

Be kind. Disagreement is fine; condescension is not.
